## 1. 一句话主线（背下来）

> **Week 01 让代码「能加载能运行」，Week 02 让请求「找得到该运行的 action」，Week 03 让数据「取得出、存得进、不拖慢」，Week 04 让行为「不改代码就能变」。**

一条链路贯穿四周：

```text
HTTP 请求 GET /api/order/detail?id=123
  │
  ├─[W1] composer autoload 按 namespace 找到所有类             ← 类从哪来
  │
  ├─[W2] web/index.php → Yii.php → config 合并 → Application::run()
  │        → 路由 module/controller/action
  │        → behaviors() 挂 Filter → loginAuth / VerifySignature  ← 谁在跑、能不能跑
  │
  ├─[W2] Controller：BaseForm 校验参数 → 调 Service
  │
  ├─[W3] Service：业务判断 → Repository：查询
  │        → ActiveRecord：find()->where()->with('goods')->one()
  │        → Redis：先查缓存，未命中再查库                        ← 数据从哪来、快不快
  │
  ├─[W4] 期间任何一步判断「开不开、返不返、显示什么」
  │        都可能是 g_config('order', 'xxx', 默认值)              ← 行为凭什么是这样
  │
  └─→ 统一 JSON 响应（code / data / info）
```

**记住这条线，四周就不是四个孤岛。**

## 3. Week 01：PHP8 + Composer + OOP（1.5 min）

### 3.1 必记四条

```text
Composer ≈ npm          composer.json ≈ package.json
vendor/ ≈ node_modules/ vendor/autoload.php ≈ 自动加载入口
PSR-4  ≈ 类在哪里（命名空间 → 目录）
PSR-12 ≈ 代码怎么排版
```

| 概念 | 正确理解 | 常错理解 |
|---|---|---|
| `use` | 建立类名短别名 | ❌ 以为它会加载文件（加载是 autoloader 干的事） |
| PSR-4 | `App\` → `src/`，`App\Services\UserService` → `src/Services/UserService.php` | ❌ 和 PSR-12 混为一谈 |
| `strict_types=1` | 收紧标量隐式转换 | ❌ 以为它等于输入校验 |
| `static::class` | 后期静态绑定，子类调用得到子类 | ❌ 用 `self::class` 导致始终是父类 |

### 3.2 OOP 的三种复用

| 机制 | 表达 | 何时用 |
|---|---|---|
| `extends` | is-a（是一种） | 建立父子层次，如 `PayController extends AuthApiController` |
| `interface` | 具备某种契约 | 只规定能力，不关心实现（PHP 的 interface **运行时存在**，TS 的编译后消失） |
| `trait` | 拥有某种能力（横向） | 多个无继承关系的类复用同一段实现；可用 `insteadof` / `as` 解冲突 |
| `abstract class` | 半成品基类 | 既给公共实现，又强制子类补 `abstract` 方法 |

### 3.3 两个真实源码收获（比语法更重要）

```php
// BaseService / BaseRepository：容器单例，不是手写 static
if (!$container->hasSingleton(static::class)) {
    $container->setSingleton(static::class);
}
return $container->get(static::class);
```

```php
// BaseRepository：主从分离的显式开关
instance($useSlave = false)   // 写后立即读 → 必须走主库，从库有复制延迟
```

> 迁移 Node 视角时最容易丢掉的一句：**PHP 通常按请求生命周期执行**，进程级状态（如静态缓存）在 FPM 下是「每进程」而非「每请求」。

## 4. Week 02：Yii2 生命周期与 Filter（1.5 min）

### 4.1 启动链（必背顺序）

```text
web/index.php
  → require vendor/autoload.php
  → require Yii.php
  → 读 config/ 并合并（main.php + main-local.php + 环境配置）
  → new yii\web\Application($config)
  → $app->run()
```

### 4.2 路由三段

```text
pay/pay/methods
 │   │   └─ actionMethods()
 │   └───── PayController        （短横线 → PascalCase：after-sale → AfterSaleController）
 └───────── pay Module          （rules 可能重写 URL，读代码时要看 urlManager）
```

### 4.3 三个不要混淆的东西

| 名字 | 是谁的 | 干什么 |
|---|---|---|
| `behaviors()` | Controller 的方法 | **声明**挂哪些 Filter |
| `Controller::beforeAction()` | 生命周期钩子 | 进入 action 前的自定义入口 |
| `Filter::beforeAction()` | Filter 类 | 真正执行登录、验签、权限 |

返回值语义：`true` 继续后续 Filter 与 action；`false` 中断。

> **本周最值钱的一句**：Filter 不一定永远先于 Controller 自定义代码——相对顺序取决于你的代码写在 `parent::beforeAction()` **前面还是后面**。
> 这正好解释了 Week 05 的 `AuthApiController`：它必须先改 `$loginAuth` 再调 `parent::beforeAction()`，因为父类调用时才第一次 `ensureBehaviors()` → `behaviors()` 读取开关。

### 4.4 BaseForm 校验

```php
$form = new CreateUserForm();
$form->load($payload, '');
if (!$form->validate()) {
    return $form->getErrors();
}
// 校验不通过，绝不进入 Service
```

| 概念 | 作用 | 别误解 |
|---|---|---|
| `rules()` | 必填/类型/长度/范围 | — |
| `scenarios()` | create/update 用不同字段子集 | 类似 Zod 的不同 schema |
| `safe` | 允许批量赋值 | ❌ 不等于数据合法 |
| `validate()` | 执行规则返回 bool | ❌ 不等于类型转换 |

### 4.5 白名单的准确含义

```text
白名单 = 免「用户登录态 / token」校验
      ≠ 免所有安全检查
```

支付 webhook 即使免登录，仍需验签、防重放、幂等、限流或来源限制。**token 有效也不代表有权访问某个订单**（归属校验在下游）。

## 5. Week 03：MySQL + Redis + ORM（1.5 min）

### 5.1 分层边界（一句话各层）

```text
Controller 接请求 → Service 管业务 → Repository 管数据访问 → Model/AR 管映射
```

| 层 | 该做 | 不该做 |
|---|---|---|
| Controller | 取参、调用、返回 | 写业务规则 |
| Service | 业务校验、流程编排、状态判断 | 拼 SQL |
| Repository | 查询/持久化，隔离 ORM 与 SQL | 知道完整业务流程 |
| Model/AR | 表映射、链式查询 | 承载跨表业务 |

### 5.2 ActiveRecord 三段式

```php
Order::find()          // 1. 建 Query
    ->where(['id' => $id])
    ->with('goods')    // 3. 预加载，消灭 N+1
    ->one();           // 2. 取一条
```

### 5.3 N+1 与 with()

```text
N+1 = 先查 1 次列表，再在循环里为每条记录额外查 1 次关联
  订单列表 1 次 + 100 个订单各查 1 次商品 = 101 次
```

| 写法 | 效果 |
|---|---|
| `$order->goods`（循环内访问） | 每次触发新查询 → N+1 |
| `->with('goods')` | 批量预加载 → 2 次查询 |
| `->joinWith('goods')` | JOIN 关联表，可参与过滤/排序 |

Node 类比：N+1 ≈ 循环里 `await findAll()`；`with()` ≈ Sequelize `include`。

### 5.4 Redis 缓存

```text
读：缓存命中 → 直接返回
    缓存未命中 → 查 MySQL → 写回缓存（设 TTL）→ 返回
写：更新 MySQL → 删缓存（延迟双删），而不是只更新缓存
```

| 点 | 记住 |
|---|---|
| 五大数据类型 | string / hash / list / set / zset |
| 为什么要封装 `OrderRedis` | 统一 key 命名、TTL、读写逻辑，避免散落 |
| 缓存三件事 | 命中率、TTL、一致性（先更库再删缓存） |
| 什么时候别缓存 | 强一致、写多读少、命中率极低的数据 |

## 6. Week 04：配置中心 + 站点 API（1.5 min）

### 6.1 `g_config` 三参数

```php
g_config(string $module, string $key, mixed $default = null): mixed
// 例：g_config('pay', 'enable_stripe', false);
// 类比：process.env.PAY_ENABLE ?? false —— 但更业务化
```

调用链（你在 Day01 阅读记录里已确认）：

```text
g_config(module, key, default)
  → ConfigHelper::config(...)
    → {NACOS_CONFIG_DIR}/{module}.ini     默认 /data/www/nacos-config
      → static $configs 同进程同 module 只读一次
```

要点：

- `g_config` **不做类型转换**，业务侧常见 `intval()` / `(string)`；
- `ConfigHelper` 用模块常量（`mall_common` / `content` / `goods` / `market` / `order` / `operate` / `pay` / `site` / `user` / `aftersale`）代替散落字符串；
- 常见坑：拼错 module 名（`'py'`）不报错，静默返回 default。

### 6.2 配置 API 链路

```text
前端 settings/config 请求
  → ConfigController（取参、返回统一 JSON）
  → ConfigService（组织业务配置、决定返回结构）
  → Helper / 配置中心（读取真实值）
  → 前端拿到可渲染的配置
```

Controller 不直接输出业务含义，Service 不输出 HTTP 响应。

### 6.3 动态 vs 静态

| 类型 | 例子 | 放哪 |
|---|---|---|
| 动态配置 | 功能开关、运营 banner、风控阈值、支付渠道开关 | 配置中心 / 后台（热更新） |
| 静态配置 | DB 连接、路由、队列名、密钥 | 环境变量 / 部署配置 |

原则：**配置项必须有默认值**；配置中心是工具，不是垃圾桶。

## 7. 跨周缝合：四周是怎么接上的（3 min 重点）

### 7.1 一条请求的完整归属表

| 阶段 | 归属周 | 具体机制 | 出问题时的症状 |
|---|---|---|---|
| 类加载 | W1 | Composer autoload / PSR-4 / Yii alias | `Class not found` |
| 入口启动 | W2 | `index.php` → `Application::run()` | 白屏 / 配置未合并 |
| 路由 | W2 | `module/controller/action` + `urlManager` | 404 |
| 鉴权 | W2 | `behaviors()` → `LoginAuthFilter` | 401 / 越权 |
| 参数 | W2 | `BaseForm::rules()` / `validate()` | 400 / 脏数据入库 |
| 业务 | W3 | `Service` | 逻辑错 |
| 数据 | W3 | `Repository` → `AR` → `MySQL` | 慢查询 / N+1 |
| 缓存 | W3 | `OrderRedis` | 数据不一致 / 击穿 |
| 行为开关 | W4 | `g_config()` | 「线上和本地表现不一样」 |

### 7.2 四周共同的三条工程原则

1. **默认关闭 / 默认拒绝**
   - W2：`loginAuth = true`（默认要登录）
   - W4：`g_config(..., $default)`（没有配置必须有兜底）
2. **收口，不收散的字符串**
   - W1：`use` 别名 + PSR-4
   - W2：`Module` 统一注册
   - W3：Repository 收口查询，`OrderRedis` 收口缓存
   - W4：`ConfigHelper` 常量收口 module/key
3. **分层不越界**
   - W1 定义分层 → W2 Controller 要薄 → W3 Repository 不写业务 → W4 Controller 不输出业务含义

### 7.3 六个高频易混点（一次过）

| 易混 | 正解 |
|---|---|
| PSR-4 vs PSR-12 | 类在哪里 vs 代码怎么排版 |
| `use` vs autoload | 别名 vs 真正加载文件 |
| `behaviors()` vs `beforeAction()` | 声明挂什么 vs 何时执行 |
| Service vs Repository | 业务规则 vs 数据访问 |
| 白名单 vs 安全放行 | 只免登录态，验签/归属校验照旧 |
| HTTP 状态码 vs 业务 code | 协议层 vs 应用层，不能互替 |

## 8. 15 分钟版快问快答（12–15 min）

> 先盖住答案，逐题口头回答。答不出的题就是你这周的缺口。

**W1**
1. `vendor/autoload.php` 做了什么？→ Composer 生成的自动加载入口，引入后按 PSR-4 等规则查类文件。
2. `use App\Foo;` 会加载文件吗？→ 不会，只建别名。
3. `static::class` 和 `self::class` 差别？→ 后者固定为定义类，前者支持后期静态绑定。
4. Trait / interface / abstract 各解决什么？→ 复用实现 / 规定契约 / 复用 + 强制补齐。
5. `strict_types=1` 能替代输入校验吗？→ 不能，HTTP 原始数据仍是字符串。

**W2**
6. Yii2 启动四步？→ autoload → Yii.php → config 合并 → `new Application()` + `run()`。
7. `pay/pay/methods` 三段对应什么？→ Module `pay` / `PayController` / `actionMethods()`。
8. 为什么 Filter 不一定先于 Controller 自定义代码？→ 顺序取决于代码在 `parent::beforeAction()` 前后。
9. `safe` 等于数据合法吗？→ 不等于，只允许批量赋值。
10. 白名单接口还需要什么？→ 验签/防重放/归属校验/限流。

**W3**
11. N+1 是什么、怎么解？→ 循环里逐条查关联；`with()` 预加载。
12. `with()` 和 `joinWith()` 区别？→ 预加载（多条查询）/ JOIN（可过滤排序）。
13. 写后立即读为什么要主库？→ 主从复制有延迟。
14. 缓存更新的推荐做法？→ 更库后删缓存，配 TTL，而非只更新缓存。
15. Repository 里能写业务判断吗？→ 不能，那是 Service 的职责。

**W4**
16. `g_config('pay','enable',false)` 三个参数含义？→ 模块 / key / 默认值。
17. `g_config` 为什么不直接返回字符串就用？→ 它不做类型转换，业务侧要显式 `intval()`。
18. 配置读取有缓存吗？→ 有，`ConfigHelper` 内 `static $configs`，同进程同 module 读一次。
19. 什么该放配置中心、什么不该？→ 运行时可调的业务开关放；DB 连接/路由/密钥不放。
20. 配置 API 里 Controller 和 Service 各做什么？→ Controller 取参返回；Service 组织配置与返回结构。

**答对 17 题以上**：阶段① 可过。
**13–16 题**：把错的那一周边再过 1 遍对应章节。
**12 题以下**：别急着进 Week 05 的 BFF，先重做该周练习。

