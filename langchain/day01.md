# Day 1：跑通离线模型，建立输入与输出的边界

> 今天你要拿到一条可解释的模型调用链，而不是只看到终端打印一句话。

**对应正文**：[01 · 全景](lessons/01-overview.md)、[02 · 模型](lessons/02-models.md)。
**适合你**：你已有 Vue/Nuxt/Node 开发经验，今天把 Promise、模块和流的经验迁移到 LLM 应用。
**边界**：七天是压缩版基础训练，不是七天获得生产级 Agent、检索或安全能力。

## 1. 今日目标

- [ ] 你能说明 LangChain、模型供应商和业务代码分别负责什么。
- [ ] 你能在没有 API key 的情况下运行两个默认离线入口。
- [ ] 你能区别 `invoke`、`batch`、`stream` 的输入、返回值与消费方式。
- [ ] 你能解释“假模型流程通过”为什么不等于“真实模型效果通过”。

## 3. 开始前的最小检查

从[课程入口](README.md)进入 `langchain/`，以下命令都在这个目录执行。
你需要 Node.js **22.12.0 或更新版本**；`.nvmrc` 固定 **26.13.1**。
若你使用 nvm，先执行 `nvm use`；否则用自己的版本管理器选择符合要求的版本。
下面的安装与复制步骤由你执行，不是本页声称已经完成的环境验证。

```bash
node --version
npm ci
cp env.example .env
```

如果已有 `.env`，不要覆盖它；对照 `env.example` 补齐配置即可。
今天保持密钥为空，也不需要设置模型名称；不要把 `.env`、真实用户输入或凭据提交到仓库。

```bash
npm run example:overview
npm run example:model
```

默认不访问模型供应商，也不自动启用 LangSmith 追踪。
`--live` 才显式选择真实供应商并可能计费；今天不需要它。

## 4. 概念速查：把 Node 经验迁移过来

| 概念 | 你熟悉的类比 | 今天必须守住的边界 |
|---|---|---|
| LangChain | 应用层 SDK 与组合工具 | 它不是模型，也不替你训练模型 |
| ChatOpenAI | 数据库驱动一类的适配器 | 接口相似不代表所有后端能力相同 |
| 消息列表 | 带角色的请求 DTO | 顺序、角色、内容结构都影响请求 |
| `invoke` | `await service.execute(input)` | 你收到消息对象，不一定是字符串 |
| `batch` | 批量任务接口 | 批量输入对应多个结果，不是拼成一个问题 |
| `stream` | `AsyncIterable` | 你逐块消费，不能把它当作完整 Promise 结果 |
| 官方假模型 | 固定响应的测试替身 | 它不理解自然语言，也没有模型推理能力 |

本课程使用 ESM、strict TypeScript 与 tsx。
示例源码是 `.ts`；NodeNext 的相对导入写 `.js`，不要直接照搬 Python 导入方式。

## 5. 源码 / 示例阅读：按调用方向走

| 阅读文件 | 你定位什么 | 你回答什么 |
|---|---|---|
| [package.json](package.json) | `example:*`、`type`、`engines` | npm 脚本真正执行哪个源码？ |
| [01-overview.ts](examples/01-overview.ts) | 环境说明与消息构造 | 哪些对象只是应用侧数据？ |
| [02-models.ts](examples/02-models.ts) | 三种调用与结果消费 | 一个结果与多个结果在哪里分开？ |
| [runtime.ts](src/runtime.ts) | 参数处理、错误出口 | 哪个条件允许进入 live 模式？ |
| [models.ts](src/models.ts) | 假模型 / ChatOpenAI 分支、文本提取 | 内容不是字符串时如何处理？ |

把调用链写成 `npm 脚本 → 示例 → 运行设置 → 模型 → 消息/消息块 → 展示`。
不要把“展示文本”当作原始响应：工具调用、内容块与元数据可能在这个步骤被省略。
先读示例实际使用的消息类型，再回到正文查术语；今天不逐页背 API。

## 6. 三个分级练习

### A · 基础：证明你走的是离线分支

- **输入**：不填任何 key，分别执行两个默认入口。
- **操作**：定位模型工厂的离线分支与 runtime 的执行设置，记录它们的文件和函数。
- **预期行为**：入口不要求供应商密钥；模型示例返回固定的假模型响应。
- **证据**：保存脱敏后的输出摘要，并标注“离线、无真实推理、未追踪”。
- **停止条件**：若默认入口提示供应商鉴权失败，先检查执行参数与工厂分支，不要填 key 掩盖问题。

### B · 进阶：比较三个输出契约

- **输入**：在你自己的练习副本中使用“解释 Promise”和“解释事件循环”两个匿名问题。
- **操作**：用 `invoke` 处理一个输入、`batch` 处理两个输入，再逐块消费 `stream`。
- **预期行为**：你拿到单个消息、两个结果以及一个可迭代的消息块序列。
- **检查**：记录原始对象类型与最终展示文本；流式块数量以实际实现为准，不预设“一字一块”。
- **反例**：换问题后假模型仍返回预设内容很正常，不能据此评价提示词质量。

### C · 挑战：设计一个不会误判的验证标准

- **输入**：一条正常消息、一组批量消息，以及模拟的非字符串内容块。
- **操作**：写出“对象形状、结果数量、文本提取、错误出口”四项验收规则。
- **预期行为**：规则既能发现应用接线错误，也明确不评价真实性、语义理解或知识覆盖。
- **加分项**：指出未来 live 验证还需记录模型、输入、耗时、错误类别与费用边界。
- **限制**：今天不用真实供应商，也不把模型列表写成永远有效的推荐。

## 8. 五道自测（附简答）

1. **LangChain 能替你提供模型能力吗？** 不能；它组织调用、消息、工具和应用流程。
2. **默认入口需要 `OPENAI_API_KEY` 吗？** 不需要；默认使用官方假模型，不调用供应商。
3. **`invoke` 返回值一定是字符串吗？** 不是；聊天模型通常返回消息对象，内容也可能是内容块。
4. **流式输出等于逐 token 输出吗？** 不一定；应用收到的是消息块，其分块策略取决于实现。
5. **离线测试能证明模型答得正确吗？** 不能；它主要证明类型、接线、控制流与确定性契约。
